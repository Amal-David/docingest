# Get started | Slinky

[Skip to content](https://docs.slinky.gg/basics/get-started/#_top)

Get started
===========

Get started using Slinky. This article assumes that you have already [purchased a license](https://slinky.gg/purchase/)
.

Loading Slinky
--------------

[Section titled “Loading Slinky”](https://docs.slinky.gg/basics/get-started/#loading-slinky)

![Startup notification after injecting](https://docs.slinky.gg/_astro/inject.PeyY6f2p_1gFFmi.webp)

After running the loader (_injecting_), you should see a notification in-game that tells you what key is currently bound to open the menu. By default this will be RSHIFT, but you can also [change it to a different key](https://docs.slinky.gg/basics/get-started/#menu-settings)
.

Navigation
----------

[Section titled “Navigation”](https://docs.slinky.gg/basics/get-started/#navigation)

![The navigation bar](https://docs.slinky.gg/_astro/nav.hxxCX4fS_Z1ckBvz.webp)

The navigation bar is located at the top of the menu. It is used to switch between different pages in the menu. If you hold down the left mouse button on the last item (_Unload_), the cheat will be unloaded.

Modules
-------

[Section titled “Modules”](https://docs.slinky.gg/basics/get-started/#modules)

The _Combat_, _Move_, _Visual_ and _Utility_ pages contain the cheat modules.

### Binds

[Section titled “Binds”](https://docs.slinky.gg/basics/get-started/#binds)

Modules can be toggled by clicking their switch in the menu, but you can also configure (key-)binds as shortcuts for toggling modules:

![Configuring a module bind](https://docs.slinky.gg/_astro/configuring-bind.CWmGo2Cf_ZtluM4.webp)

Instead of pressing the desired bind, you can also left click again or press ESC to change the bind back to `NONE`.

Binds will normally turn the module on or off each time they are pressed, but they can also be configured to enable a module while the key is pressed, then disable when the key is released. This is done by hovering over the bind, then toggling the `HOLD` option.

![The require hold setting for binds](https://docs.slinky.gg/_astro/hold-bind.BWIwz7hX_2qGKcy.webp)

### Settings

[Section titled “Settings”](https://docs.slinky.gg/basics/get-started/#settings)

![Example of a collapsed module](https://docs.slinky.gg/_astro/collapsed.BfdVLPGh_Z25HoFu.webp) ![Example of an expanded module](https://docs.slinky.gg/_astro/expanded.CvnwaSZe_1K3k5y.webp)

The settings for a module can be revealed by pressing the `+` button.

Profiles
--------

[Section titled “Profiles”](https://docs.slinky.gg/basics/get-started/#profiles)

![The profiles page](https://docs.slinky.gg/_astro/profiles.BVi9pNfi_ZoANip.webp)

Any settings you change (except for _GUI_) are not automatically saved; they must be stored in a profile if you wish to keep them. You can create an infinite number of different profiles, which can be saved or loaded at any time.

Menu settings
-------------

[Section titled “Menu settings”](https://docs.slinky.gg/basics/get-started/#menu-settings)

![The GUI settings](https://docs.slinky.gg/_astro/mod-gui.DgAVCIRV_Zlzw8j.webp)

Under the _Visual_ tab, you will find the _GUI_ module, which lets you configure the keybind for the menu and some other settings.

# Linux usage | Slinky

[Skip to content](https://docs.slinky.gg/basics/linux/#_top)

Linux usage
===========

Slinky supports Linux, however it may require some additional setup compared to the Windows version.

Requirements
------------

[Section titled “Requirements”](https://docs.slinky.gg/basics/linux/#requirements)

*   Only tested on [Arch Linux](https://archlinux.org/)
    . Support for other distros is currently not guaranteed. Musl-based distros are unlikely to work at all.
*   Supports X11, XWayland & native Wayland. Keep in mind that Minecraft 1.7.10 & 1.8.9 do not run on Wayland natively without mods.
*   The loader and Minecraft processes must be ran as the same user (this will usually be the case anyway). Root privileges are not required.
*   Some third-party launchers (Lunar/Badlion) require a [workaround](https://docs.slinky.gg/basics/linux/#injection-workaround)
     to allow injecting into them.

Install libcurl
---------------

[Section titled “Install libcurl”](https://docs.slinky.gg/basics/linux/#install-libcurl)

Before you can run Slinky, make sure that `libcurl` is installed by running the following command in a terminal:

*   [Arch Linux](https://docs.slinky.gg/basics/linux/#tab-panel-0)
    
*   [Debian/Ubuntu](https://docs.slinky.gg/basics/linux/#tab-panel-1)
    
*   [Fedora](https://docs.slinky.gg/basics/linux/#tab-panel-2)
    

    sudo pacman -S curl

    sudo apt install curl

    sudo dnf install libcurl-minimal

Installation instructions
-------------------------

[Section titled “Installation instructions”](https://docs.slinky.gg/basics/linux/#installation-instructions)

1.  [Download Slinky](https://slinky.gg/download)
    .
    
    *   Directory/example
        
        *   slinky-loader
        
    
2.  Open a terminal in the directory where you saved the loader and allow executing it by running the following command:
    
        chmod +x slinky-loader
    
3.  Create the following file (make sure to replace `/example/` with the directory where you saved the loader):
    
        [Desktop Entry]Type=ApplicationName=SlinkyExec=/example/slinky-loaderTerminal=true
    
4.  _(Flatpak only)_: If you are running Minecraft via Flatpak (for example using Prism Launcher), you will probably need to exempt the Slinky data directory from the Flatpak sandbox:
    
        sudo flatpak override org.prismlauncher.PrismLauncher --filesystem=~/.slinky
    
    If you are not using Flatpak, you can ignore this step.
5.  You can now use the newly created desktop icon to run Slinky.

Injection workaround
--------------------

[Section titled “Injection workaround”](https://docs.slinky.gg/basics/linux/#injection-workaround)

Some third-party launchers (such as Lunar/Badlion) block the injection method used by Slinky. The following steps explain how to bypass them.

1.  [Download injectpatch.so](https://docs.slinky.gg/injectpatch.so)
     and the launcher you want to use.
    
    *   Directory/example
        
        *   injectpatch.so
        *   LunarClient.appimage
        
    
2.  Create the following script (make sure to replace `/example/` with the directory where you saved the files):
    
        #!/bin/bashLD_PRELOAD=/example/injectpatch.so /example/LunarClient.appimage
    
3.  Open a terminal in the directory where you saved the script and allow executing it by running the following command:
    
        chmod +x run-patched.sh
    
4.  You can now run `run-patched.sh` to run the patched launcher.

# Auto Tool | Slinky

[Skip to content](https://docs.slinky.gg/modules/block/auto-tool/#_top)

Auto Tool
=========

The _Auto Tool_ module automatically selects the correct tool when clicking on a block.

Activation time
---------------

[Section titled “Activation time”](https://docs.slinky.gg/modules/block/auto-tool/#activation-time)

Configures a minimum duration where the player has to be holding down the mouse button before the module activates. Can be set to `0 ms` to remove any delay.

Switch back when done
---------------------

[Section titled “Switch back when done”](https://docs.slinky.gg/modules/block/auto-tool/#switch-back-when-done)

If enabled, _Auto Tool_ will switch back to your previous slot when you are done mining.

Allow while using
-----------------

[Section titled “Allow while using”](https://docs.slinky.gg/modules/block/auto-tool/#allow-while-using)

You can enable various categories of items where _Auto Tool_ may activate when they are being held:

*   Sword
*   Tool
*   Fists
*   Other (applies to all other items)

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/block/auto-tool/#conditions)

To prevent accidentally switching tools, eg. when you accidentally click a block while in combat, the module can be configured to only activate while sneaking.

### Restrict allowed blocks

[Section titled “Restrict allowed blocks”](https://docs.slinky.gg/modules/block/auto-tool/#restrict-allowed-blocks)

If enabled, you can specify a list of block types where _Auto Tool_ may activate when they are being mined.

# Bridge Assist | Slinky

[Skip to content](https://docs.slinky.gg/modules/block/bridge-assist/#_top)

Bridge Assist
=============

The _Bridge Assist_ module automatically sneaks for you when you are near the edge of a block. This allows you to build bridges very quickly, without the risk of falling.

Edge offset
-----------

[Section titled “Edge offset”](https://docs.slinky.gg/modules/block/bridge-assist/#edge-offset)

![Edge offset values visualized](https://docs.slinky.gg/_astro/edge-offset.C6rRAJ1H_Z2eKD7j.webp)

In Minecraft, you can walk a slight distance away from the edge of a block before you actually fall off. This setting specifies how far you are allowed to go before _Bridge Assist_ will start sneaking.

Specifying a higher value, means the player will start sneaking later and therefore bridge faster.

Unsneak delay
-------------

[Section titled “Unsneak delay”](https://docs.slinky.gg/modules/block/bridge-assist/#unsneak-delay)

Specifies how long the player should keep sneaking, even after a block has been placed already.

Higher values means the player will sneak longer and therefore bridge slower.

Select blocks
-------------

[Section titled “Select blocks”](https://docs.slinky.gg/modules/block/bridge-assist/#select-blocks)

Configures whether _Bridge Assist_ should select blocks from your hotbar:

### No

[Section titled “No”](https://docs.slinky.gg/modules/block/bridge-assist/#no)

Never select blocks automatically

### On depletion

[Section titled “On depletion”](https://docs.slinky.gg/modules/block/bridge-assist/#on-depletion)

Don’t select blocks, unless you were already holding a stack and you just placed the last block.

### Always

[Section titled “Always”](https://docs.slinky.gg/modules/block/bridge-assist/#always)

Always select blocks, regardless of what item you were holding previously.

Randomize
---------

[Section titled “Randomize”](https://docs.slinky.gg/modules/block/bridge-assist/#randomize)

If enabled, the [Edge offset](https://docs.slinky.gg/modules/block/bridge-assist/#edge-offset)
 and [Unsneak delay](https://docs.slinky.gg/modules/block/bridge-assist/#unsneak-delay)
 settings will be randomized. This setting is typically only necessary on servers with good anti-cheats, to avoid getting detected for being too consistent.

Sneak on jump
-------------

[Section titled “Sneak on jump”](https://docs.slinky.gg/modules/block/bridge-assist/#sneak-on-jump)

Sneaks when you jump to make it less likely that you fall off while bridging upwards.

Avoid double-sneaking
---------------------

[Section titled “Avoid double-sneaking”](https://docs.slinky.gg/modules/block/bridge-assist/#avoid-double-sneaking)

Delays block placements until you are positioned properly when bridging diaognally, which avoids the issue where you start sneaking twice per block.

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/block/bridge-assist/#conditions)

You can specify additional requirements that must be met to activate _Bridge Assist_:

*   Sneak key pressed
*   Holding blocks
*   Looking down
*   Not moving forward

# Fast Place | Slinky

[Skip to content](https://docs.slinky.gg/modules/block/fast-place/#_top)

Fast Place
==========

In vanilla Minecraft, there is a delay between block placements when holding down the right mouse button. _Fast Place_ removes this delay, allowing you to place blocks very quickly.

Maximum CPS
-----------

[Section titled “Maximum CPS”](https://docs.slinky.gg/modules/block/fast-place/#maximum-cps)

Limits the maximum clicks per second generated by _Fast Place_. Some anti-cheats will cancel block placements when going above a certain speed threshold, so this setting can be used to prevent that.

Activate delay
--------------

[Section titled “Activate delay”](https://docs.slinky.gg/modules/block/fast-place/#activate-delay)

Specify a delay before _Fast Place_ activates. For example, if you set this to `200 ms`, then you will have to hold down your right mouse button (or whatever bind you use to place blocks) for 200 milliseconds before _Fast Place_ increases your block place speed.

# Fast Mine | Slinky

[Skip to content](https://docs.slinky.gg/modules/block/fast-mine/#_top)

Fast Mine
=========

_Fast Mine_ allows you to mine blocks faster than vanilla.

Speed
-----

[Section titled “Speed”](https://docs.slinky.gg/modules/block/fast-mine/#speed)

Specifies the multiplier for the block mining speed.

Break delay
-----------

[Section titled “Break delay”](https://docs.slinky.gg/modules/block/fast-mine/#break-delay)

Vanilla Minecraft waits 250ms after breaking a block before you are able to start mining again. This setting allows you to reduce that delay.

Always decrease break delay
---------------------------

[Section titled “Always decrease break delay”](https://docs.slinky.gg/modules/block/fast-mine/#always-decrease-break-delay)

In vanilla Minecraft, the delay after breaking a block only ‘counts down’ while trying to break the next block. This means that if you break a block, immediately stop mining and then try to mine a block several minutes later, the game would still apply the delay before breaking the second block.

With this setting enabled, the delay will always count down each tick, regardless of whether you are trying to mine another block. Note that this has no affect if you already set your `Break delay` to 0.

# Aim Assist | Slinky

[Skip to content](https://docs.slinky.gg/modules/combat/aim-assist/#_top)

Aim Assist
==========

The _Aim Assist_ module moves your crosshair onto other players for you.

Mode
----

[Section titled “Mode”](https://docs.slinky.gg/modules/combat/aim-assist/#mode)

_Aim Assist_ can be used in several different modes.

### Regular

[Section titled “Regular”](https://docs.slinky.gg/modules/combat/aim-assist/#regular)

This mode will feel the same as the aim assist in most other cheats. The further your crosshair is away from the target, the faster it will move.

### Linear

[Section titled “Linear”](https://docs.slinky.gg/modules/combat/aim-assist/#linear)

Unlike [Regular](https://docs.slinky.gg/modules/combat/aim-assist/#regular)
, this mode uses an (almost) linear speed. It is better at tracking players at low speed, but it cannot perform fast snaps (eg. when an enemy throws an enderpearl). This mode is best suited if you already have decent aim and just want to get a slight advantage.

### Lock-on

[Section titled “Lock-on”](https://docs.slinky.gg/modules/combat/aim-assist/#lock-on)

This mode removes any delay altogether and just instantly places your crosshair on the target. It is extremely blatant and should be used with care.

### Silent

[Section titled “Silent”](https://docs.slinky.gg/modules/combat/aim-assist/#silent)

This mode will not move your screen/camera when aiming on targets, making it feel more like ‘Kill Aura’ modules seen in other cheats (except it does not click for you). This is mainly a cosmetic feature, other players will see you aim on them as usual.

#### Keep move direction

[Section titled “Keep move direction”](https://docs.slinky.gg/modules/combat/aim-assist/#keep-move-direction)

If disabled, your player will walk in the direction where the module is aiming in _Silent_ mode. It may be difficult to move like this in gamemodes like Sky Wars, where you need to jump across islands a lot, so you can enable this setting to instead move in the direction the camera is facing.

Whether this setting is on or off, _Silent_ mode will never generate movements that are impossible in vanilla Minecraft.

#### Ignore manual aim

[Section titled “Ignore manual aim”](https://docs.slinky.gg/modules/combat/aim-assist/#ignore-manual-aim)

By default, your manual aim can override the silent look if you aim towards the target faster. If this setting is disabled, your own mouse movements will be ignored entirely (except to move the game camera).

Speed
-----

[Section titled “Speed”](https://docs.slinky.gg/modules/combat/aim-assist/#speed)

You can configure horizontal and vertical speed separately. If you want to disable vertical aiming, you can put the speed on zero (keep in mind that [Silent](https://docs.slinky.gg/modules/combat/aim-assist/#silent)
 mode will always aim vertically).

Multipoint
----------

[Section titled “Multipoint”](https://docs.slinky.gg/modules/combat/aim-assist/#multipoint)

![Aim positions for different horizontal multipoint settings](https://docs.slinky.gg/_astro/multipoint.r18UI1sM_AgaAs.webp)

The _Multipoint_ sliders lets you control at which point the module will aim. A value of `0%` will always use the center of the target’s hitbox as aiming position. A value of `100%` will aim at point in the target’s hitbox that is closest to the player, which is usually one of the corners. Any other value will aim between these two points, with `50%` aiming exactly in the middle of them.

You can configure the horizontal and vertical axes separately.

Predict
-------

[Section titled “Predict”](https://docs.slinky.gg/modules/combat/aim-assist/#predict)

If set to a value above `0%`, _Aim Assist_ will aim to the position the player is moving towards, which may be a little bit ahead of their current position. This can be especially helpful when using lower speed values. Note that a high _Predict_ value combined with high aim speed may result in _Aim Assist_ overshooting so much that you end up missing hits.

Randomization
-------------

[Section titled “Randomization”](https://docs.slinky.gg/modules/combat/aim-assist/#randomization)

Controls the aim position randomization strength, with `0%` resulting in the highest accuracy (no randomization at all) and `100%` the lowest accuracy.

Lowering this value can cause detection in some cases. If you are unsure what value to use, we recommend just leaving it on the default `50%`.

Target
------

[Section titled “Target”](https://docs.slinky.gg/modules/combat/aim-assist/#target)

_Aim Assist_ lets you configure exactly how and when targets should be selected.

### Mode

[Section titled “Mode”](https://docs.slinky.gg/modules/combat/aim-assist/#mode-1)

Targets can be selected using one of two modes.

#### Single

[Section titled “Single”](https://docs.slinky.gg/modules/combat/aim-assist/#single)

Using the _Single_ mode, the module will stay locked on to targets. It will prefer to aim to players who are closest to your crosshair already. It will not switch to a different target, even if they are closer, as long as the original target is still valid.

##### Increased FOV while locked

[Section titled “Increased FOV while locked”](https://docs.slinky.gg/modules/combat/aim-assist/#increased-fov-while-locked)

If enabled, this will increase your maximum FOV while you are locked onto a target. For example, assuming you are using a maximum FOV of 100, _Aim Assist_ will not lock onto any players outside of that FOV. However, once you find a target within a FOV of 100, it will then continue tracking the player even if they move outside of it. This will reset once you lose the target, for example because they move too far away or because another condition isn’t met.

#### Switch

[Section titled “Switch”](https://docs.slinky.gg/modules/combat/aim-assist/#switch)

This mode will always aim on the nearest player. If another player moves closer, the module will switch on to them, even if the original target was still valid.

##### Sort by

[Section titled “Sort by”](https://docs.slinky.gg/modules/combat/aim-assist/#sort-by)

When using _Switch_ target mode, you can configure how the optimal target is chosen.

###### Distance

[Section titled “Distance”](https://docs.slinky.gg/modules/combat/aim-assist/#distance)

The closest player will be chosen.

###### Health

[Section titled “Health”](https://docs.slinky.gg/modules/combat/aim-assist/#health)

The player with the lowest health will be chosen.

###### Hurt time

[Section titled “Hurt time”](https://docs.slinky.gg/modules/combat/aim-assist/#hurt-time)

The least recently damaged player will be chosen.

###### Aim angle

[Section titled “Aim angle”](https://docs.slinky.gg/modules/combat/aim-assist/#aim-angle)

The player closest to your crosshair will be chosen.

Range
-----

Clutch
======

The _Clutch_ module places blocks underneath you when you are about to fall.

Range
-----

[Section titled “Range”](https://docs.slinky.gg/modules/block/clutch/#range)

Determines how far to scan for a block to clutch against. This is measured by the total number of blocks that would need to be placed to reach it.

FOV
---

[Section titled “FOV”](https://docs.slinky.gg/modules/block/clutch/#fov)

Determines the field of view used when scanning for blocks to clutch against.

Minimum height
--------------

[Section titled “Minimum height”](https://docs.slinky.gg/modules/block/clutch/#minimum-height)

The minimum number of air blocks that must be below you in order for _Clutch_ to activate.

Click speed
-----------

[Section titled “Click speed”](https://docs.slinky.gg/modules/block/clutch/#click-speed)

The maximum speed at which _Clutch_ may place blocks.

Randomization
-------------

[Section titled “Randomization”](https://docs.slinky.gg/modules/block/clutch/#randomization)

Controls the randomization strength of various parts of the module. Higher randomization may help with avoiding anti-cheat flags, but it can also make the module feel less consistent.

Select blocks
-------------

[Section titled “Select blocks”](https://docs.slinky.gg/modules/block/clutch/#select-blocks)

Configures whether _Clutch_ should automatically select blocks from your hotbar:

### No

[Section titled “No”](https://docs.slinky.gg/modules/block/clutch/#no)

Never select blocks automatically

### On depletion

[Section titled “On depletion”](https://docs.slinky.gg/modules/block/clutch/#on-depletion)

Don’t select blocks, unless you were already holding a stack and you just placed the last block.

### Always

[Section titled “Always”](https://docs.slinky.gg/modules/block/clutch/#always)

Always select blocks, regardless of what item you were holding previously.

Only place sideways
-------------------

[Section titled “Only place sideways”](https://docs.slinky.gg/modules/block/clutch/#only-place-sideways)

If enabled, _Clutch_ will only place against the sides of other blocks. This can be used to maintain the same Y level while clutching (but note that it can still go up by placing blocks along an existing wall).

Aim
---

[Section titled “Aim”](https://docs.slinky.gg/modules/block/clutch/#aim)

_Clutch_ offers various settings to control the overall speed.

### Base speed

[Section titled “Base speed”](https://docs.slinky.gg/modules/block/clutch/#base-speed)

The base speed before it is modified by the other speed-related settings. If you want _Clutch_ to rotate faster or slower, this is generally the setting you want to change.

### Acceleration

[Section titled “Acceleration”](https://docs.slinky.gg/modules/block/clutch/#acceleration)

_Clutch_ can adjust the rotation speed depending on how wide the remaining angle is. Higher values will result in faster rotations.

### Acceleration strength

[Section titled “Acceleration strength”](https://docs.slinky.gg/modules/block/clutch/#acceleration-strength)

The [Base Speed](https://docs.slinky.gg/modules/block/clutch/#base-speed)
 and [Acceleration](https://docs.slinky.gg/modules/block/clutch/#acceleration)
 settings are combined to determine the final speed, this setting controls how strongly the [Acceleration](https://docs.slinky.gg/modules/block/clutch/#acceleration)
 setting affects the result.

Some examples of values for this setting:

*   `0%`: only [Base Speed](https://docs.slinky.gg/modules/block/clutch/#base-speed)
     is used, [Acceleration](https://docs.slinky.gg/modules/block/clutch/#acceleration)
     is ignored entirely
*   `100%`: only [Acceleration](https://docs.slinky.gg/modules/block/clutch/#acceleration)
     is used, [Base Speed](https://docs.slinky.gg/modules/block/clutch/#base-speed)
     is ignored entirely
*   `50%`: both [Base Speed](https://docs.slinky.gg/modules/block/clutch/#base-speed)
     and [Acceleration](https://docs.slinky.gg/modules/block/clutch/#acceleration)
     affect the final speed equally

### Multipoint

[Section titled “Multipoint”](https://docs.slinky.gg/modules/block/clutch/#multipoint)

If enabled, _Clutch_ will always try to aim to the nearest point on the block. It is usually recommended to leave this off, since the advantage is small and it makes your aim snap around a lot.

Snap-back
---------

[Section titled “Snap-back”](https://docs.slinky.gg/modules/block/clutch/#snap-back)

The previous section configures the part where _Clutch_ aims from your original crosshair position to a block. This section controls the opposite; snapping back to your original crosshair position after it has clutched.

### Delay

[Section titled “Delay”](https://docs.slinky.gg/modules/block/clutch/#delay)

Determines how long _Clutch_ waits after placing a block before rotating back.

### Duration

[Section titled “Duration”](https://docs.slinky.gg/modules/block/clutch/#duration)

Determines how long the rotation back takes. The [Delay](https://docs.slinky.gg/modules/block/clutch/#delay)
 is not included in this duration.

### Keep jump direction

[Section titled “Keep jump direction”](https://docs.slinky.gg/modules/block/clutch/#keep-jump-direction)

If enabled, _Clutch_ will snap back instantly when the player jumps (turning the module into a ‘Telly scaffold’).

### Disable afterwards

[Section titled “Disable afterwards”](https://docs.slinky.gg/modules/block/clutch/#disable-afterwards)

If enabled, _Clutch_ disables itself after it has rotated back to your original crosshair position.

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/block/clutch/#conditions)

_Clutch_ can be configured to only activate if:

*   You are mid-air, landing on ground will disable the module. Note that due to the way Minecraft movement works, it is possible to slide off the edge of a block after landing. Whether this affects you mostly depends on how you use the module, however you can pair it with [Bridge Assist](https://docs.slinky.gg/modules/block/bridge-assist/)
     to avoid as well.
*   You recently took damage
*   You are moving backwards (like when taking knockback)

# Backtrack | Slinky

Backtrack
=========

The _Backtrack_ module will lag other players when they are about to move out of range, allowing you to get additional hits on them.

This module is mainly intended to be used on servers where regular reach cheats are detected. Since _Backtrack_ is fully lag based, it does not violate vanilla Minecraft mechanics.

Target distance
---------------

[Section titled “Target distance”](https://docs.slinky.gg/modules/combat/backtrack/#target-distance)

Specifies at which distances _Backtrack_ may activate. For example, when set to `1.0 - 4.0 blocks`, _Backtrack_ will not activate for players closer than 1 block or further away than 4 blocks.

Maximum delay
-------------

[Section titled “Maximum delay”](https://docs.slinky.gg/modules/combat/backtrack/#maximum-delay)

Configures the maximum amount of time that the module may block packets for. Higher values mean players will be kept closer for a longer time, therefore offering more time to hit them.

Maximum hurt time
-----------------

[Section titled “Maximum hurt time”](https://docs.slinky.gg/modules/combat/backtrack/#maximum-hurt-time)

Limits how high the target’s hurt time can be before _Backtrack_ activates (a hurt time of `200 ms` here means that the player can be damaged again in 200 milliseconds, ignoring latency). Keep in mind that any setting below the maximum will make _Backtrack_ activate in spikes, rather than applying a constant smooth lag.

Cooldown
--------

[Section titled “Cooldown”](https://docs.slinky.gg/modules/combat/backtrack/#cooldown)

Allows setting a delay after _Backtrack_ deactivates. For example, if you set this value to `1.0 s` and _Backtrack_ lags a player who then goes out of range, at least one second must pass before it can start lagging again.

Real position indicator
-----------------------

[Section titled “Real position indicator”](https://docs.slinky.gg/modules/combat/backtrack/#real-position-indicator)

When enabled, the module will render a box that indicates where the player would be standing if there was no lag. There are various options that can be customized:

*   Color
*   Line width
*   Filled (if false, only an outline is drawn)
*   Apply head rotation (the box will rotate based on where the player is aiming)

Disable on hit
--------------

[Section titled “Disable on hit”](https://docs.slinky.gg/modules/combat/backtrack/#disable-on-hit)

Immediately stops lagging if you take knockback.

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/combat/backtrack/#conditions)

You can configure the module to only activate when you are holding a weapon.

# Hit Select | Slinky

[Skip to content](https://docs.slinky.gg/modules/combat/hit-select/#_top)

Hit Select
==========

The _Hit Select_ module filters unnecessary clicks, which helps reduce your average click speed whilst reducing more knockback.

Pause duration
--------------

[Section titled “Pause duration”](https://docs.slinky.gg/modules/combat/hit-select/#pause-duration)

Controls the maximum duration that the module will prevent clicks. There are no perfect values here, it all depends on your own personal preference. Using higher values here means you will be able to move faster and have a lower average click speed (this does not cause you to take more knockback).

Mode
----

[Section titled “Mode”](https://docs.slinky.gg/modules/combat/hit-select/#mode)

_Hit Select_ can be used in several modes.

### Burst

[Section titled “Burst”](https://docs.slinky.gg/modules/combat/hit-select/#burst)

This mode will only allow you to click when your target can actually take damage and cancel clicks otherwise. This prevents you from slowing yourself down with unnecessary hits, allowing you to move faster.

#### Wait for first hit

[Section titled “Wait for first hit”](https://docs.slinky.gg/modules/combat/hit-select/#wait-for-first-hit)

When set to a nonzero value, _Hit Select_ will not attack until you get hit first or until the configured delay has passed. This implements the mechanic that people generally refer to as 'hit selecting' and can be beneficial to start combos.

#### Hit later in trades

[Section titled “Hit later in trades”](https://docs.slinky.gg/modules/combat/hit-select/#hit-later-in-trades)

Similar to [Wait for first hit](https://docs.slinky.gg/modules/combat/hit-select/#wait-for-first-hit)
, except this configures the delay for hits afterwards. Waiting slightly longer to get hit in trades will usually reduce more knockback and keep your click speed lower too, however since it will also slow down your attacks it can make it harder to deal a lot of knockback to your target.

### Criticals

[Section titled “Criticals”](https://docs.slinky.gg/modules/combat/hit-select/#criticals)

This mode will prevent you from clicking while moving upwards (usually after taking knockback), which allows you to delay your attack until you are falling. Minecraft only lets you get critical hits while falling, so this module will greatly increase the chance of that happening.

#### Disable during knockback

[Section titled “Disable during knockback”](https://docs.slinky.gg/modules/combat/hit-select/#disable-during-knockback)

If enabled, _Hit Select_ will not attempt to land more critical hits while you are taking knockback. You should usually only enable this if you are using the [Use server attack time](https://docs.slinky.gg/modules/combat/hit-select/#use-server-attack-time)
 setting as well.

#### Only while damaged

[Section titled “Only while damaged”](https://docs.slinky.gg/modules/combat/hit-select/#only-while-damaged)

If enabled, _Hit Select_ will wait for you to get hit before it tries to land critical hits.

Use server attack time
----------------------

[Section titled “Use server attack time”](https://docs.slinky.gg/modules/combat/hit-select/#use-server-attack-time)

If enabled, rather than trying to predict when a player will take damage the client will wait for the server to confirm it. This means that the check will be affected by your ping (which is why you should generally not enable this), however it is a useful alternative for when the default attack prediction does not work.

Fake swing
----------

[Section titled “Fake swing”](https://docs.slinky.gg/modules/combat/hit-select/#fake-swing)

It may feel strange to see your sword stop swinging while playing, so this setting can be enabled to always display the swing animation, even when you are not really clicking/swinging. This is purely a cosmetic feature, other players or anti-cheats can't tell the difference.

Cancel rate
-----------

[Section titled “Cancel rate”](https://docs.slinky.gg/modules/combat/hit-select/#cancel-rate)

Specifies the chance of actually cancelling a click. For example, if you use `50%` chance while clicking 20 CPS, it will result in you clicking 10 CPS on average (50% of the original speed).

### In combat

[Section titled “In combat”](https://docs.slinky.gg/modules/combat/hit-select/#in-combat)

Configures the cancel rate in combat. This only affects hits that are predicted to not deal damage, so using a high value here will not make you land less hits.

*   On `100%` this will result in each hit being perfectly timed and it will let you move as fast as possible.
*   On `0%` this effectively disables _Hit Select_ in combat.
*   For a more legit looking click pattern, you will likely want to use a value somewhere in between (it can be useful to use a mod that shows your click speed to find a value that produces realistic clicks).

### Missed swings

[Section titled “Missed swings”](https://docs.slinky.gg/modules/combat/hit-select/#missed-swings)

Configures the cancel rate for missed swings (swinging at air rather than a player). This setting never affects your hits on players. Instead, it is useful to keep your average click speed lower by reducing it when you don't need to be swinging.

*   On `100%` you will only ever swing when aiming on a player. This means the lowest average click speed, but also makes it look more like a triggerbot (since you never miss a hit).
*   On `0%` this effectively disables _Hit Select_ for missed hits.
*   For a more legit looking click pattern, try using a value that isn't too high to reduce your average click speed, without creating long noticeable pauses.

# Velocity | Slinky

[Skip to content](https://docs.slinky.gg/modules/combat/velocity/#_top)

Velocity
========

The _Velocity_ module is used to reduce the knockback you take.

Mode
----

[Section titled “Mode”](https://docs.slinky.gg/modules/combat/velocity/#mode)

_Velocity_ can be used in several modes.

### Regular

[Section titled “Regular”](https://docs.slinky.gg/modules/combat/velocity/#regular)

Regular mode simply reduces your motion to the specified amount. Modern anti-cheat plugins that feature good movement validation will generally catch this mode on any setting.

#### Chance

[Section titled “Chance”](https://docs.slinky.gg/modules/combat/velocity/#chance)

Specifies the chance of your knockback being reduced.

#### FOV

[Section titled “FOV”](https://docs.slinky.gg/modules/combat/velocity/#fov)

Any knockback originating outside the field of view specified by this setting will **not** be reduced.

Some example values:

*   `360°`: reduce knockback from all angles _(default)_
*   `180°`: reduce knockback if hit from the front, but don’t reduce when hit in the back (useful to prevent being slowed down while running away)

#### Reduce to

[Section titled “Reduce to”](https://docs.slinky.gg/modules/combat/velocity/#reduce-to)

Specifies the amount of knockback that will be retained. If you set it to `60%`, you will receive 60% of the intended knockback amount.

#### Reduce delay

[Section titled “Reduce delay”](https://docs.slinky.gg/modules/combat/velocity/#reduce-delay)

Specifies a delay before your knockback is reduced. For example, if you set it to `1 tick`, you will receive full knockback during the first game tick, then reduced knockback during the second.

### Jump

[Section titled “Jump”](https://docs.slinky.gg/modules/combat/velocity/#jump)

_Jump_ mode will automatically jump immediately after receiving knockback. This abuses a vanilla Minecraft mechanic, which lets you (partially) negate your knockback if you jump right away.

#### Chance

[Section titled “Chance”](https://docs.slinky.gg/modules/combat/velocity/#chance-1)

Specifies the chance of jumping when taking knockback.

### Reduce

[Section titled “Reduce”](https://docs.slinky.gg/modules/combat/velocity/#reduce)

Abuses the vanilla attack slowdown mechanic (_reducing_) to reduce your knockback. This mode allows you to reduce knockback in cases where vanilla Minecraft does not allow it.

#### Allow for double-clicks

[Section titled “Allow for double-clicks”](https://docs.slinky.gg/modules/combat/velocity/#allow-for-double-clicks)

If checked, your knockback will be reduced for double-clicks as well, which by default do not affect your motion.

### Ignore

[Section titled “Ignore”](https://docs.slinky.gg/modules/combat/velocity/#ignore)

This mode is similar to using _Regular_ at `0%`, except that you don’t lose any speed when getting hit.

#### Vertical

[Section titled “Vertical”](https://docs.slinky.gg/modules/combat/velocity/#vertical)

_Ignore_ is the only mode that lets you modify vertical velocity.

##### Never

[Section titled “Never”](https://docs.slinky.gg/modules/combat/velocity/#never)

Using this setting, vertical velocity is always applied.

##### Only in air

[Section titled “Only in air”](https://docs.slinky.gg/modules/combat/velocity/#only-in-air)

Using this setting, vertical velocity is cancelled if you are hit mid-air.

##### Always

[Section titled “Always”](https://docs.slinky.gg/modules/combat/velocity/#always)

Using this setting, vertical velocity is always cancelled.

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/combat/velocity/#conditions)

You can control when your knockback is reduced using the following conditions:

*   Looking at player
*   Mouse pressed
*   Moving forward
*   Holding weapon
*   Sprinting ([Jump](https://docs.slinky.gg/modules/combat/velocity/#jump)
     mode only; when enabled, this also prevents jump-resetting when already reducing your knockback by clicking on a player in the same game tick)

[Skip to content](https://docs.slinky.gg/modules/utility/fake-lag/#_top)

Fake Lag
========

The _Fake Lag_ module adds artificial lag to your connection.

Mode
----

[Section titled “Mode”](https://docs.slinky.gg/modules/utility/fake-lag/#mode)

_Fake Lag_ can be used in two modes.

### Static

[Section titled “Static”](https://docs.slinky.gg/modules/utility/fake-lag/#static)

In _Static_ mode, the delays you specify are simply added to your ping and won’t fluctuate. Conditions can still cause fluctuations, eg. switching items when using _Holding weapon_ requirement can cause the module to toggle on and off.

### Pulse

[Section titled “Pulse”](https://docs.slinky.gg/modules/utility/fake-lag/#pulse)

In _Pulse_ mode, packets will be held back, then flushed in pulses. It is similar to manually spamming the [Blink](https://docs.slinky.gg/modules/utility/blink/)
 module repeatedly.

Delay
-----

[Section titled “Delay”](https://docs.slinky.gg/modules/utility/fake-lag/#delay)

You can configure _Inbound_ and _Outbound_ delay separately. If you set both sliders to `50 ms`, your ping will increase by `50 + 50 = 100 ms`.

You can also enable _Realtime damage_. This setting only affects the _Inbound_ delay. When enabled, it will not delay damage packets, so you will immediately see when you or your target take damage, while still delaying other things such as knockback.

Conditions
----------

[Section titled “Conditions”](https://docs.slinky.gg/modules/utility/fake-lag/#conditions)

By default _Fake Lag_ just adds a static delay to your connection, but it can be turned into dynamic lag by enabling conditions:

*   Holding weapon
*   Require attack (meaning you recently attacked another player)
*   In-game (disables in menus)

# Notifications | Slinky

[Skip to content](https://docs.slinky.gg/modules/visual/notifications/#_top)

Notifications
=============

![Examples of cheat notifications](https://docs.slinky.gg/_astro/notifications.CJffoVyF_14qsjg.webp)

_Notifications_ configures the notifications displayed by the cheat.

Hide if
-------

[Section titled “Hide if”](https://docs.slinky.gg/modules/visual/notifications/#hide-if)

Enable scenarios where notifications are not shown. Can be enabled for:

*   `In-game`: hides notifications when the mmenu isn’t open
*   `Hold bind is used`: hides notifications for modules with a bind in hold mode
*   `Module is bind-only`: hides notifications for bind-only modules (like [Auto Pot](https://docs.slinky.gg/modules/utility/auto-pot/)
    )

Visible mod categories
----------------------

[Section titled “Visible mod categories”](https://docs.slinky.gg/modules/visual/notifications/#visible-mod-categories)

Controls which module categories generate notifications. For example, you may not want to receive notifications when toggling modules like _Free Look_ or _Player ESP_, so you can disable the _Visual_ category.

# Player ESP | Slinky

[Skip to content](https://docs.slinky.gg/modules/visual/player-esp/#_top)

Player ESP
==========

The _Player ESP_ module highlights other players, allowing you to find them more easily.

Range
-----

[Section titled “Range”](https://docs.slinky.gg/modules/visual/player-esp/#range)

Specifies the maximum rendering range. Blocks further away will not be highlighted.

Hide friendlies
---------------

[Section titled “Hide friendlies”](https://docs.slinky.gg/modules/visual/player-esp/#hide-friendlies)

If enabled, teammates and friends are ignored.

Customization
-------------

[Section titled “Customization”](https://docs.slinky.gg/modules/visual/player-esp/#customization)

The looks of the ESP boxes can be customized.

### Style

[Section titled “Style”](https://docs.slinky.gg/modules/visual/player-esp/#style)

Configures the ESP style. Both styles support toggling the box and health bar independently.

#### 2D

[Section titled “2D”](https://docs.slinky.gg/modules/visual/player-esp/#2d)

![The 2D Player ESP style](https://docs.slinky.gg/_astro/player-esp-2d.mjQeFLDO_1VbDsM.webp)

#### 3D

[Section titled “3D”](https://docs.slinky.gg/modules/visual/player-esp/#3d)

![The 3D Player ESP style](https://docs.slinky.gg/_astro/player-esp-3d.BgVbKYum_dtpd4.webp)

### Hurt effect

[Section titled “Hurt effect”](https://docs.slinky.gg/modules/visual/player-esp/#hurt-effect)

If enabled, the ESP will flash red when damaged, similar to what happens to the vanilla player model.

### Line width

[Section titled “Line width”](https://docs.slinky.gg/modules/visual/player-esp/#line-width)

Adjust how thick the outlines are.

### Filled

[Section titled “Filled”](https://docs.slinky.gg/modules/visual/player-esp/#filled)

When turned off, only an outline will be rendered.

### Colors

[Section titled “Colors”](https://docs.slinky.gg/modules/visual/player-esp/#colors)

_Player ESP_ has contains two modes for determining colors. Both modes additionally support an _Override target color_ setting that allows using a different color for the current [Aim Assist](https://docs.slinky.gg/modules/combat/aim-assist/)
 target.

#### Automatic

[Section titled “Automatic”](https://docs.slinky.gg/modules/visual/player-esp/#automatic)

The ESP color will match the player’s name tag color.

#### Manual

[Section titled “Manual”](https://docs.slinky.gg/modules/visual/player-esp/#manual)

You can configure a custom color for enemies and friendlies.

# Trajectories | Slinky

[Skip to content](https://docs.slinky.gg/modules/visual/trajectories/#_top)

Trajectories
============

The _Trajectories_ module displays the predicted path when holding items like bows or ender pearls.

Line width
----------

[Section titled “Line width”](https://docs.slinky.gg/modules/visual/trajectories/#line-width)

Specifies how thick the rendered lines are.

Colors
------

[Section titled “Colors”](https://docs.slinky.gg/modules/visual/trajectories/#colors)

Specifies the colors used for successful and unsuccessful paths. The definition of what is considered successful depends on the item, eg. hitting an entity with a bow is considered a hit, but hitting a block is considered a miss.

Render uncharged bow
--------------------

[Section titled “Render uncharged bow”](https://docs.slinky.gg/modules/visual/trajectories/#render-uncharged-bow)

If enabled, holding an uncharged bow will make the module render the path as if it was fully charged.

# Pointers | Slinky

[Skip to content](https://docs.slinky.gg/modules/visual/pointers/#_top)

Pointers
========

![Screenshot while using Pointers](https://docs.slinky.gg/_astro/pointers.BNlzrD4o_WIaTn.webp)

The _Pointers_ module displays arrows around your crosshair pointing to other players. It allows seeing where players are at, even if they are outside of your field of view.

Range
-----

[Section titled “Range”](https://docs.slinky.gg/modules/visual/pointers/#range)

Specifies the maximum rendering range. No pointer will be rendered for players outside this range.

Ignore within FOV
-----------------

[Section titled “Ignore within FOV”](https://docs.slinky.gg/modules/visual/pointers/#ignore-within-fov)

No pointer will be rendered for players within the FOV specified by this setting. You can use this if you only want to see pointers to players you can’t already see on your screen. You can also simply set this to 0 degrees to always point to all players.

Hide friendlies
---------------

[Section titled “Hide friendlies”](https://docs.slinky.gg/modules/visual/pointers/#hide-friendlies)

If enabled, teammates and friends are ignored.

Customization
-------------

[Section titled “Customization”](https://docs.slinky.gg/modules/visual/pointers/#customization)

Pointers offers various customization settings.

### Style

[Section titled “Style”](https://docs.slinky.gg/modules/visual/pointers/#style)

Currently you can choose between two styles.

#### 2D

[Section titled “2D”](https://docs.slinky.gg/modules/visual/pointers/#2d)

Pointers are always rendered flat on the screen.

#### 3D

[Section titled “3D”](https://docs.slinky.gg/modules/visual/pointers/#3d)

Pointers will be rendered at an angle, creating a better feeling of depth.

### Colors

[Section titled “Colors”](https://docs.slinky.gg/modules/visual/pointers/#colors)

There are various modes available to generate pointer colors.

#### Distance

[Section titled “Distance”](https://docs.slinky.gg/modules/visual/pointers/#distance)

Each pointer will be colored based on the distance to the player it points to. The _Near_ and _Far_ colors can be customized.

#### Name Tag

[Section titled “Name Tag”](https://docs.slinky.gg/modules/visual/pointers/#name-tag)

The pointer will use the same color as the name tag of the player it points to.

#### Manual

[Section titled “Manual”](https://docs.slinky.gg/modules/visual/pointers/#manual)

This mode lets you choose a color yourself. You can select a separate color for enemies and friendlies.

### Transition between

[Section titled “Transition between”](https://docs.slinky.gg/modules/visual/pointers/#transition-between)

Specifies which distances are considered near and far. This affects colors when using _Distance_ mode and also the _Distance-based radius_ setting. For example, if you are using the default _Distance_ colors and specify a value of `10 - 50 blocks` for this setting, any players within a 10 block radius will be fully red, while any players outside a 50 block radius will be fully green.

### Scale

[Section titled “Scale”](https://docs.slinky.gg/modules/visual/pointers/#scale)

Controls the size of the pointers.

### Radius

[Section titled “Radius”](https://docs.slinky.gg/modules/visual/pointers/#radius)

Controls how far the pointers are rendered from your crosshair.

### Distance-based radius

[Section titled “Distance-based radius”](https://docs.slinky.gg/modules/visual/pointers/#distance-based-radius)

If enabled, pointers for players that are far away will also be rendered further away from your crosshair.

# Inv Manager | Slinky

[Skip to content](https://docs.slinky.gg/modules/utility/inv-manager/#_top)

Inv Manager
===========

_Inv Manager_ manages various parts of your inventory for you.

Delay after open
----------------

[Section titled “Delay after open”](https://docs.slinky.gg/modules/utility/inv-manager/#delay-after-open)

Specifies a delay between opening your inventory and _Inv Manager_ performing the first click.

Speed
-----

[Section titled “Speed”](https://docs.slinky.gg/modules/utility/inv-manager/#speed)

Specifies how fast _Inv Manager_ may move items in your inventory.

Smart speed
-----------

[Section titled “Smart speed”](https://docs.slinky.gg/modules/utility/inv-manager/#smart-speed)

If enabled, _Inv Manager_ will automatically adjust the speed depending on how the items are laid out. For example, items laid out in a perfect row next to eachother can be moved quickly, while items scattered throughout your inventory will be moved more slowly. This makes your actions appear a lot more legitimate.

Randomize
---------

[Section titled “Randomize”](https://docs.slinky.gg/modules/utility/inv-manager/#randomize)

If enabled, randomizes the [Delay after option](https://docs.slinky.gg/modules/utility/inv-manager/#delay-after-open)
 and [Speed](https://docs.slinky.gg/modules/utility/inv-manager/#speed)
 settings.

Equip armor
-----------

[Section titled “Equip armor”](https://docs.slinky.gg/modules/utility/inv-manager/#equip-armor)

If enabled, the best armor pieces in your inventory will be equipped automatically.

Sort hotbar
-----------

[Section titled “Sort hotbar”](https://docs.slinky.gg/modules/utility/inv-manager/#sort-hotbar)

If enabled, automatically sorts your hotbar for you. An item can be assigned to each slot. If you find a better item (eg. a diamond sword, while having an iron sword equipped) the module will replace the old one automatically.

### Smart fallbacks

[Section titled “Smart fallbacks”](https://docs.slinky.gg/modules/utility/inv-manager/#smart-fallbacks)

If enabled, various fallbacks will be used if the item you assigned to a slot could not be found:

*   If you don’t have a sword, the item with the highest attack damage will be used instead
*   If you don’t have a fishing rod, snowballs/eggs will be used instead
*   If you don’t have a snowballs/eggs, a fishing rod will be used instead
